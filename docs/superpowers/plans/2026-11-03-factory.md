# Pitwall Factory Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: use superpowers:subagent-driven-development (implement → spec/code review → fix) task by task. Read `CLAUDE.md` first: its rules are binding.

**Spec (binding):** `docs/superpowers/specs/2026-11-03-factory-design.md`. Where this plan and the spec disagree, the spec wins. Write down any deviation in the progress log.

**Branch:** `factory`. Commit after each task with all tests passing, then **push**.

**Progress log:** `docs/superpowers/progress-factory.md`. Update it after every task with:
- the commits;
- the test counts;
- any deviations;
- anything left for LOCAL.

A new session starts by reading that log and continues from the first task not marked done.

**Tests:**
- Hub: `python -m pytest hub -q`. On Windows, add `--basetemp X:/_pytest_tmp/<name>`.
- Factory: `python -m pytest factory -q`.
- Dashboard (if touched): `npx vitest run --maxWorkers=2` and `npx tsc -b` in `dashboard/`.

**Task types:**
- **CLOUD:** can be built and fully tested on Linux.
- **LOCAL:** needs the user's Windows PC: Inno Setup, Edge, the real signing key, rendering. Cloud sessions must **not** attempt LOCAL tasks. Where a CLOUD task touches Windows-only files (pitwall.iss, .ps1), edit them carefully and cover them with static tests (as `hub/tests/test_packaging.py` does). The real compile happens in LOCAL.

## CLOUD tasks (in order)

### C1. Licence core (hub)
- Add `cryptography>=42` to `pyproject.toml` dependencies and install it.
- `hub/simtelemetry/licence_pubkey.py`:
  - `TRUSTED_KEYS: tuple[bytes, ...] = ()`, holding raw 32-byte Ed25519 public keys.
  - It is empty until LOCAL task L1 adds the real key. A comment says so.
- `hub/simtelemetry/licence.py`:
  - **Parsing:** `parse(code)` reads `PW1-<b64url payload>.<b64url sig>`, tolerating spaces and line breaks pasted around it.
  - **Verifying:** `verify(code, keys=TRUSTED_KEYS) -> Licence | LicenceError`. Errors carry plain-English messages (spec §2.3).
  - **Payload model:** a pydantic model of the spec §2.2 fields.
  - **Entitlements:** a dataclass with rigs, games, features, variant, cafe_name, licence_id, cafe_id, seq and `source` ("licence" or "fallback").
  - **Fallback:** `FALLBACK` gives 4 rigs, `["f1_25"]`, every `FeaturesConfig` field and variant "9t7".
  - **Accepting a new code:** `accept_new(current, new)` applies the same-cafe and higher-seq rules.
- **Tests (`hub/tests/test_licence.py`):** use keys generated inside the test (monkeypatch `TRUSTED_KEYS`). Cover:
  - a round trip;
  - a payload byte flip;
  - a wrong key;
  - truncation and a wrong prefix;
  - garbage input;
  - whitespace tolerance;
  - the seq and cafe rules;
  - the fallback when the key list is empty.

### C2. Licence storage, owner page, backups
- **Storage:** the licence lives at `<data>\licence.txt`.
  - It is loaded at hub start; if missing or invalid, the fallback is used plus an admin warning: "No licence found. Contact your supplier." (or "The licence file is damaged…").
  - It is written atomically.
  - It is added to backups (`core/backup.py` BACKED_UP_FILES) and restored with them.
- **Hub:** `Hub.entitlements` (a property), and `Hub.apply_licence(code)` re-applies everything live (C3 hooks) and pushes a feed refresh.
- **Owner API:**
  - `GET /api/owner/licence` returns the summary.
  - `POST /api/owner/licence` takes `{code}`, is guarded by the owner PIN and the shared `PinAttempts` lock-out, and returns plain errors from spec §2.3.
- **Owner page:** a Licence card ("Licensed to {cafe} · {rigs} rigs · {games}", the licence id, and an "Enter new code" box). Text is set via `textContent`.
- **Setup page:** shows a read-only licence summary line.
- **Tests:** the API happy path; each error; lock-out; backup include and restore; hot apply.

### C3. Enforcement (hub feed and pages)
- **Licensed rigs:** the first N by rig number. Helper: `entitlements.licensed(rig_number)`.
- **Feed to the TV:** frames, rig_info, boards and moments only include licensed rigs. Unlicensed rigs still record laps in the DB and on staff boards.
- **Staff page:** a rig card shows "Not licensed".
- **Warning** on staff Health and the owner page: "This licence covers N rigs. Rig N+1 and up aren't shown on the TV. Contact {supplier} to add rigs." `{supplier}` is "9T7 Racing" or "your supplier" depending on the variant.
- **Features:** the effective `[features]` are the hub.toml flags AND the licensed features, applied wherever `config.features` is read. Prefer one accessor, e.g. `hub.features_effective` or wrapping the config at load.
- **Games:** packets from an unlicensed game are dropped, with a Health line: "This licence doesn't include <game>". Today only f1_25 exists, so test this through the adapter registry with a fake game id.
- **Variant:** a new additive `hub.vendor_mark: bool` in the snapshot and feed, documented in `docs/WS_SCHEMA.md`. Pages hide any "9T7 Racing" mark when it is false. Find them with `git grep -n "9T7\|POWERED BY"`.
- **Tests:** feed filtering; staff marks; warning wording for both variants; feature AND-ing; game drop; vendor_mark.

### C4. Dashboard
- The TV hides the "POWERED BY" vendor block (`dashboard/src/components/Pitwall.tsx`, around line 190) and any 9T7 mark when `hub.vendor_mark` is false.
- Rig filtering comes from the feed. Add a defensive test that the TV never renders a rig missing from rig_info.
- vitest coverage for both.

### C5. Provisioning (hub)
- **`hub/simtelemetry/provision.py` and CLI `Pitwall.exe provision <dir> [--check] [--force-other-cafe]`:**
  - `<dir>` holds `profile.json` (the subset baked by the factory: cafe_id, name, tagline, logo file name, accent, wifi, hours, rigs, rig_names, games, features, variant), the logo and `licence.txt`.
  - **Fresh install** (no settings.json, or `setup_done` false and no `cafe_id` stamp):
    - write the licence;
    - pre-fill settings.json with the cafe fields and **no PINs**, keeping `setup_done=false`;
    - write `rig_names` as pending names (rigs.json keeps them by rig number, applied as rigs register);
    - write hub.toml `[features]`, preserving the rest of the file;
    - stamp `<data>\cafe.json` with `{cafe_id, name}`.
  - **Upgrade** (stamp present, same `cafe_id`): only install the licence if it is newer (`accept_new`). Never touch settings, PINs, rig names, logo or Wi-Fi.
  - **Different cafe:** exit with code 3 and a plain message "This installer is for {other}. This PC belongs to {cafe}.", unless `--force-other-cafe`.
  - `--check` performs only the cafe check (for the installer's early refusal).
- **Tests:** fresh vs upgrade (never overwrites, with a check on every field); wrong cafe; force; check-only; hub.toml preserved; bad input dir.

### C6. Installer support (static edits; compile is LOCAL)
- **`packaging/pitwall.iss`:**
  - An optional `#ifdef ProfileDir` that bakes `{#ProfileDir}\*` into `{tmp}\profile`.
  - In `PrepareToInstall`, before stopping the hub, run `<existing exe> provision <tmp> --check` when the hub is already installed, and refuse with its message on exit code 3.
  - After the files are in, run `provision` before the hub starts.
  - The output file name becomes `Pitwall-Setup-<CafeSlug>.exe` when defined.
  - `AppPublisher` and `VersionInfoCompany` come from a `Vendor` define: "9T7 Racing" or blank for unbranded. Blank means no company string, and the installer text never says 9T7.
  - Without `ProfileDir`, the generic installer works exactly as now.
- **`packaging/build.ps1`:** new parameters `-ProfileDir`, `-Vendor` and `-InstallerOnly`. `-InstallerOnly` skips PyInstaller when `dist\Pitwall\` plus `dist\Pitwall\build-stamp.json` match the current version and commit. The build writes that stamp.
- **Tests:** static checks in `hub/tests/test_packaging.py` for the new defines, ordering, the exit-code handling and that no "9T7" is hard-coded outside the Vendor define.

### C7. Factory: profile, pricing, presets
- New top-level package `factory/` (not shipped to cafes; excluded from PyInstaller), with `factory/tests/` and an `__main__.py` launching the app (C12).
- **`factory/profile.py`:** a pydantic `CafeProfile` per spec §2.1.
  - `features` is generated from `simtelemetry.config.FeaturesConfig` fields.
  - `games` come from the hub's adapter registry.
  - Presets: `FULL` and `BASIC`. BASIC turns off events, head_to_head, owner, challenges and race_podium; confirm the list in a code comment.
  - Plain-English checks: `profile.problems() -> list[(field, message)]`.
  - Slug and file name helpers.
  - Load and save are atomic.
- **`factory/pricing.py`:** `retail_price(rigs)` gives ₹20,000 for up to 4 rigs, plus ₹5,000 for each extra; the unbranded variant gets no default. `upgrade_price(old, new)` covers extra rigs. Game and feature add-on prices are entered by hand; record that as a decision in the log.
- **Tests:** every validation message; presets; pricing; round trip; the contact data never appears in `licence_payload()` or `baked_profile()`.

### C8. Factory: keys and licence issue
- **`factory/keys.py`:**
  - Folder: `%APPDATA%\PitwallFactory\keys\`, or `$XDG_CONFIG_HOME/PitwallFactory/keys` elsewhere; tests use tmp.
  - `create_keys()` refuses to overwrite.
  - `load_private()`.
  - `public_key_py()` renders the `licence_pubkey.py` contents.
  - Backup state: `backed_up_to`, plus `copy_backup(dest)`.
  - On Windows, the private key file gets a user-only ACL via `icacls` (Windows only; skipped in tests).
- **`factory/licence_issue.py`:**
  - `issue(profile, keys, seq)` returns the code. It must round-trip through `simtelemetry.licence.verify`.
  - The next seq per cafe comes from the profile history.
- **Tests:** issue then verify (with the test key injected into `TRUSTED_KEYS`); seq increments; no overwrite of keys; the private key never written inside a given Shipments path.

### C9. Factory: documents
- **Templates in `factory/templates/`:**
  - `guide.html`;
  - `certificate.html`, which includes a QR code of the licence via segno;
  - `upgrade_certificate.html`;
  - `README.txt`.
  - Variant-aware: the 9t7 variant uses the 9T7 Racing logo (from `factory/assets/brand/`); unbranded uses only the Pitwall name and the cafe logo.
  - Content per spec §2.6. The F1 25 settings come from the same source text as RIG_SETUP (U1).
- **`factory/docs.py`:**
  - `render_html(kind, profile, licence)` uses `string.Template` or a minimal Jinja-free renderer (no new dependency).
  - `html_to_pdf(html_path, pdf_path)` uses Edge headless (`--headless=new --print-to-pdf`), with path detection and a plain error if Edge is missing.
  - The PDF step is mocked in CLOUD tests.
- **Tests:** both variants render; the unbranded output contains no "9T7"; the price breakdown is correct; HTML escaping of cafe text (`<script>` in a cafe name is shown as text).

### C10. Factory: build pipeline
- **`factory/build.py`:** implements the spec §2.5 pipeline.
  - `build_package(profile, settings, runner)`. `runner` abstracts subprocess calls (build.ps1/ISCC, Edge) so tests inject fakes.
  - Staging happens in a temp folder, then an atomic rename to `<Shipments>\<Cafe> (<date>)`; a second build the same day gets a suffix.
  - **Verification:** re-read the staged licence; verify it; compare cafe_id, rigs and variant; check every file exists and is non-empty; scan unbranded generated files for "9T7".
  - Appends to the history.
  - `rebuild_all()` returns a summary.
  - `issue_upgrade(profile)` returns the code and the upgrade certificate PDF.
  - Cancellation: a `threading.Event` checked between steps; on cancel, clean up staging.
- **Videos:** `factory/assets/video/{9t7,unbranded}.mp4`. Missing videos give the plain problem "Guide video for this variant is missing." (filled in by LOCAL L3).
- **Tests:** a happy path with fakes; failure at each step leaves no package; verification catches a tampered licence and a stray "9T7"; history; rebuild-all summary; upgrade; cancel.

### C11. Factory: preview
- **`factory/preview.py`:** `start_preview(profile)` does the following:
  1. Makes a temp data dir.
  2. Runs `provision` into it.
  3. Picks a free port, never 8000.
  4. Starts `python -m simtelemetry run --demo --data-dir <tmp> --http-port <port>`, or the built exe when present.
  5. Waits for `/api/health`.
  6. Opens Edge windows: the TV `/`, `/staff`, and a 430×900 check-in window.

  `stop()` kills the process tree and deletes the temp dir.
- Demo mode must honour the provisioned licence and branding. Check this; adjust `--demo` if it currently ignores settings.
- **Tests:** command building; port never 8000; cleanup; health wait with a fake server.

### C12. Factory: the form app
- **`factory/app.py`, tkinter (ttk):** the layout per spec §2.8. Field validation shows `profile.problems()` next to the fields. The buttons are Preview, Build package, Issue upgrade, Rebuild all and Open shipments folder.
  - A red banner shows until the key backup is done, and there is a "Set up keys" first-run flow.
  - Long jobs run in a worker thread, with a progress bar and Cancel.
  - Errors are shown in plain English, with a "Show details" button for the log.
  - No network.
- **Launcher:** `Pitwall Factory.cmd` at the repo root runs `.venv\Scripts\pythonw -m factory`.
- **Docs:** a "Factory (seller only)" section in `README.md` covering how to start it, the key backup and the workflow (new cafe → preview → build → ship; add-on → Issue upgrade; new Pitwall version → Rebuild all).
- **.gitignore:** `Shipments/`, `*.key`, `factory/assets/video/*.mp4` (large files are kept locally), and `profiles/`.
- **Tests:** a smoke test that constructs the window under xvfb (skip if no display); the controller logic is separated from widgets and unit-tested.

### C13. Whole-branch review
- Review `git diff hardening..HEAD` against the spec and CLAUDE.md. Fix any Critical or Important findings.
- Make sure all hub, factory and dashboard tests pass.
- Update the progress log with a **LOCAL hand-off list**: exactly what the LOCAL session must build and check.

## LOCAL tasks (user's Windows PC, after the cloud work)

- **L1 Keys:** run the factory, "Set up keys", back them up to USB, commit the generated `licence_pubkey.py`, and rebuild the Pitwall program.
- **L2 Real builds:** build two sample cafes, one 9t7 with 6 rigs and one unbranded with 4 rigs and a custom price. Inspect the installers (publisher, name), the PDFs and the README.
- **L3 Unbranded video:** render from the brag-output composition with the 9T7 marks swapped for the Pitwall wordmark. Copy both videos into `factory/assets/video/`.
- **L4 Preview:** check it by eye for both cafes.
- **L5 Spare PC:** fresh install of one package; set PINs; check the branding is pre-filled and the licence card; apply an upgrade code; run the wrong-cafe installer and confirm it's refused.
- **L6 Merge** into `packager` and push.
